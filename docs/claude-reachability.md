# Claude 网页可达性验证

可达性分为网关后台请求与受控浏览器正常打开网页两条路径。两侧独立显示，结果不能互相代替；访问风险中的出口国家规则继续独立计分。

- 网关使用现有 HTTP 传输请求 claude.ai，不发送登录 Cookie 或 API Key，不执行页面脚本。`cf-mitigated: challenge` 才标记 Cloudflare 验证；没有该证据的 403 只标记“拒绝访问，原因未确认”。401、403、429 或明确验证响应均不计验证分，不增加访问风险。连接失败与网站 5xx 仍保留失败结果。
- 跨站脚本的 opaque 响应不提供状态码，也不能证明登录页或应用加载成功。Claude 侧这类结果暂不计分。
- 在“claude.ai 可达性”详情中点击“打开受控浏览器验证”。它复用现有受控浏览器会话；没有窗口时才启动，不修改系统代理、时区或个人浏览器资料。
- 在窗口内人工完成验证或登录，再点击“完成验证后复检”。详情打开时每 3 秒读取一次页面状态。主文档成功响应且页面加载完成后，浏览器侧才通过可达性检测；登录页、普通页面、显示账号菜单与输入框的页面分别说明验证边界。
- 只观察主文档响应及必要的页面结构，返回状态类别、状态码、连接错误类别和采样时间，不返回页面文字、完整 URL、聊天内容、Cookie 或账号资料。不会自动发送消息。
- 页面关闭、离开 claude.ai、浏览器连接丢失或代理地址发生变化后，不复用旧的通过结果。浏览器关闭或助手重启后，需要重新打开验证；登录资料仍由受控浏览器自己的独立目录管理。

“页面已加载”表示当前窗口已有成功导航的页面证据，不等于持续在线监控或聊天消息成功。网络或节点调整后，应在该窗口刷新网站再复检；更换代理地址时需通过原有浏览器接入流程重新连接。

修改需重启本机助手及前端开发服务才能生效；已安装的桌面应用需重新打包更新。本功能不要求先开启模拟保护。

验证：`npm run test:reachability`。专项覆盖真实 Chromium 的验证页、登录页、应用界面、DNS 失败、关闭页面和代理变化，以及状态分类、敏感数据排除和计分边界。该 Chromium 测试使用本地受控响应，不代表已经通过线上 Cloudflare 验证或真实账号聊天验证。
