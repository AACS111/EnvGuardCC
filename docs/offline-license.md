# Claude 桌面账号离线授权码生成器

## 启动和签发

在项目根目录运行 `npm run license:generator`，或双击 `tools/license-generator/start.cmd`。需要 Node.js 20 或更新版本；无需新增依赖、注册账号或连接授权服务器。生成器只监听随机的 `127.0.0.1` 端口，Windows 上会尝试打开默认浏览器，也可手动打开终端显示的本机地址。

若需独立使用，运行 `npm run license:package`：会在 `node_modules/.checkcc-dist/` 创建新的 Windows x64 工具目录和 ZIP，内置当前 Node.js 运行时，解压后双击根目录的“启动授权码生成器.cmd”即可。该目录可单独复制到签发者电脑，不需要完整项目；每次打包创建新目录，不覆盖旧工具，也不会自动迁移旧私钥。已签发过授权时，应安全迁移并复用原私钥，避免公钥更换后旧授权无法验签。首次启动后生成的私钥目录不应再对外分发。

1. 输入 Claude 桌面账号的 UUID。必须来自真实账号信息；邮箱、组织 UUID、设备 ID 不适用。UUID 格式校验无法区分同为 UUID 的组织 ID，签发者须核对来源。生成器不证明账号所有权，也不读取 Claude 凭证。
2. 设置首次成功激活后可用的天数，范围 1–3650 天。
3. 点击“生成授权码”，复制完整代码或保存 `.license.json` 文件发给用户。
4. 授权码必须在生成后 3600 秒内首次激活，到达截止时刻即失效。激活后的使用期限单独计算。例如 14:00 签发、14:30 激活、可用 30 天：15:00 不会使已激活授权失效。

界面按本机时区显示时间；授权内容使用 UTC 秒时间戳。签发依赖签发者电脑的时钟，签发前应校准时间。重新点击生成会产生新的授权编号和新的激活窗口，不会修改先前签发的代码。

## 密钥管理和交付

首次启动自动创建 `.checkcc-license-issuer/issuer-private.pem` 和 `issuer-public.pem`。此目录已加入 Git 忽略规则。后续启动复用同一私钥，损坏或无法解密时停止，不会静默换钥。

私钥只属于签发者，须单独备份。可在首次启动前设置环境变量 `CHECKCC_ISSUER_PASSPHRASE`，使新私钥采用 AES-256-CBC 加密；此后每次启动须提供同一口令。给已有未加密私钥设置此变量不会自动加密旧文件。未设置口令时私钥依赖本机文件权限保护，Node 的 POSIX mode 不能代替 Windows ACL。

使用“导出验签公钥”取得 `.pem` 公钥，供主应用固定内置。授权码或授权文件不包含私钥和原始账号 UUID，但账号摘要并不是加密，不应作为隐私保护承诺。不要把签发工具、私钥目录交给最终用户。当前桌面打包只拷贝明确列出的运行目录，不会包含 `tools/` 或 `.checkcc-license-issuer/`。

## 主应用接入边界

`scripts/license-verifier.mjs` 仅使用公钥，提供：

- `verifyLicenseForActivation(code, publicKey, { accountUuid, now })`：验签、核对当前账号、检查一小时激活窗口，返回激活时间和使用到期时间。
- `verifyActivatedLicense(code, publicKey, { accountUuid, activatedAt, lastSeenAt, now })`：验证已激活授权、检测时间回退、核对当前账号、检查使用期限。激活后的校验不会再次要求处于一小时激活窗口内。

`now` 为 UTC 秒，默认取当前本机时间。只有可信账号识别模块才能传入 `accountUuid`，不能使用用户手填值、授权码自带值或可修改的本地账号字段作为当前身份。激活记录必须使用操作系统提供的保护存储，例如 Electron safeStorage；不要直接信任客户端提交的 `activatedAt` 或 `lastSeenAt`。并发操作须串行保存历史最大时间，重复提交同一授权不得重置首次激活时间。

**本次交付生成器和验签模块，尚未把主应用改成强制激活。** 已检查本机 Claude 3.6556.2：活跃账号由进程内部维护，常规配置没有可直接读取的活跃账号字段；HTTPS 代理也不能从透传的加密数据中取得身份。尚无经过验证、能在切号后可靠更新的离线账号来源。因此没有添加假账号识别或使用手填 UUID 冒充当前账号。后续须先确定真实身份来源，再接入用户已选择的单页激活界面和后端功能门禁。

纯离线不能严格抵抗系统时间回拨、整机快照回滚或阻止同一授权在多台机器重复激活；也无法远程吊销。历史时间记录只能提高绕过成本。主应用接入时应保留退出、关闭保护、恢复原始配置等必要操作，不能因过期而阻断恢复。

## 验证

运行 `npm run test:license`。测试覆盖真实签发与公钥验签、账号不匹配、激活时间边界、激活后使用期限、时间回退、内容篡改、密钥复用、并发初始化及本机生成器的跨站请求防护。
