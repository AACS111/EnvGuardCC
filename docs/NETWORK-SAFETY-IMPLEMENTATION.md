## 启动前与其他 VPN 交接（2026-11-07）

开启系统接管、严格模式，以及恢复已保存的 TUN 意愿时，先处理其他代理工具，再启用隧道。独立本机代理启动不主动退出其他客户端。

- macOS 对当前用户的 FlClash、Clash Verge/Rev、ClashX/Pro、Clash for Windows、Surge、Stash、Hiddify、Karing 发出正常退出请求；识别同时检查应用包名和主程序名。Windows 对当前交互会话的 FlClash、Clash Verge、Clash for Windows、Hiddify、Karing、v2rayN 请求关闭主窗口，并复核 PID 对应的程序路径。
- 等待客户端及可归属到已识别 macOS 应用包的代理内核退出。root 常驻助手或自动重启内核没有释放客户端、出口或端口时，暂停接管并提示手动关闭后台服务；不按 `mihomo`/`clash` 名字强杀，不停其他用户的 GUI。独立的 Xray/Mihomo 服务可能是自托管节点，不能仅凭进程名判定它正在抢占系统网络；保留这类服务，由路由、系统代理和端口检查判断实际冲突。
- macOS 继续检查已连接的系统 VPN、默认 IPv4 出口是否仍为其他隧道，以及是否残留其他工具的 HTTP/HTTPS/SOCKS/PAC/自动代理。未知 VPN 不能安全自动退出时明确报错。冷启动还验证 EGCC 需要的控制器/本机代理端口能否绑定。
- 进程和资源检查失败会阻止 TUN 启动；已有本机代理切换失败时保持原配置。单个系统命令有 5 秒超时，交接流程设 20 秒预算并在每步结束后复核，不无限等待。正常退出其他客户端后不会在 EGCC 失败或退出时自动重启它们。
- 界面显示检查、退出、等待和剩余冲突原因。Windows 的窗口退出逻辑有回归覆盖，尚无 Windows 实机验证；Windows 没有同等的未知 VPN 路由/系统代理全量检测。此检测也不构成所有分流 VPN、多网卡和 IPv6 路径均已排除的证明。

新增回归见 `scripts/check-network-takeover.mjs`，使用隔离进程清单和命令注入，普通测试不会退出本机真实 VPN。

## 已实现

- 网络页提供独立的系统接管开关。首次默认不接管系统网络；成功后保存接管意愿。本机 HTTP/SOCKS 代理默认仍为 `127.0.0.1:39080`。日常代理无需开启环境适配。
- 保护启动在后台先启用并核验 TUN，再识别固定出口、应用环境配置。恢复环境完成后才解除接管；解除失败保留恢复状态与备份。页面不再分别发两条启停命令。
- 后台每 5 秒检查内核接口和启用时的隧道探测，失败后串行恢复并退避；普通网卡地址变化使旧出口缓存失效并增加网络代次。显式停止会终止监测，不会被健康检查自动启动。
- 导入、来源切换、刷新、模式和网络配置变更串行执行。新节点配置或模式启动失败会抛错并尝试恢复旧配置；回滚失败会显式报告。自动订阅更新移除或修改当前固定节点时，保留旧配置，要求用户手动确认新配置。
- 配置规则先拒绝目标 UDP/443，再匹配目标域名。校验器检查顺序，避免通用域名规则抢先命中。
- 热加载先把原选择编译成默认节点，再加载一次配置；原节点不存在时拒绝加载；加载后核验实际选择，失败不会报告成功。此过程仍不等于系统级零泄漏。
- 主内核及临时探测内核使用随机控制器密钥，密钥不进入状态报告。真实内核测试验证未认证的 `/proxies` 请求返回 401。
- 固定出口探测通过专用入站绑定实际节点，独立于普通流量组。环境目标优先使用此路径；失败不拿普通组的出口代替。
- 节点解析 DNS 跟随每个来源保存和切换；旧版顶层 DNS 只迁移到原 active 来源。出口 A→B→A 计为两次变化，并发记录串行写入，空记录不宣称稳定。
- 接管未知或路由采样超过 45 秒时不显示成功；状态轮询失败时废弃旧的成功证据。路由结论限定为内核观察到的连接。
- 特权宿主拒绝配置目录/文件的符号链接逃逸、未知顶层字段和缺少控制器密钥的配置，在私有目录运行验证过的配置副本。
- 特权安装器复制独立的 Node、宿主代码、依赖、内核和内核许可材料。macOS 目录由 root 管理且去除普通用户写权限；Windows 安装路径使用管理员/SYSTEM ACL。系统启动脚本清理 Node 注入环境，Windows 使用 UAC 编码命令处理路径。旧宿主需要重新安装；这些权限安装步骤尚需实机验收。
- macOS 可选严格模式使用固定的 `com.apple/000.envguardcc` PF 子 anchor。先阻断、清理既有连接状态，再启动专属 `utun90`；固定出口探测符合基线且专属路由确认后才放行 TUN。全部出站只使用一个固定节点，不继承内网或订阅直连例外。
- PF 规则独立于应用和 mihomo 存活。宿主失联、内核退出或网卡变化时保留阻断；退出应用也不自动解除。重启宿主时从私有记录恢复阻断，普通启停不能绕过已启用的严格模式。
- 严格模式只允许已验证的节点 IP/端口，以及回环、IPv4 DHCP、链路本地 IPv6 邻居发现等必要控制流量。只管理自己的子 anchor 与 PF 启用引用，不重新加载或清空系统主规则。当前只接受已检查的 Apple 默认入口；自定义主规则、可能抢先放行的子 anchor、NAT 或 skip 布局会拒绝启用。
- 严格模式启用私有本机代理认证。暂停期间本机 API 网关返回 503，防止普通本机代理设置或网关业务请求绕过暂停。每 30 秒检查固定出口变化；观测到变化后保持阻断，重连时必须匹配原基线。周期检查不能保证在供应商切换出口后的第一条请求前发现变化。
- 提供独立的 `/Library/PrivilegedHelperTools/com.envguardcc.kernel-recover` 恢复入口；不依赖页面、节点列表或原主规则仍然兼容。卸载前先解除本程序的阻断，不执行全局 `pfctl -d`。
- 宿主与独立恢复工具使用跨进程锁及持久化解除意愿。恢复后旧实例重新读取状态，旧会话的恢复请求也会因版本不符而拒绝，不会被健康检查自动封回去；启动前拒绝占用中的 `utun90`，不借用其他 VPN 网卡。

## 如何使用

1. 运行开发版或重新构建桌面版，导入自己的订阅或自托管节点。只含 provider、没有内联 `proxies` 的 Clash 配置仍不支持；导入会使用 EGCC 的分组和规则，并非完整迁移原策略组。
2. 选择固定节点。网络页可测速、检测各节点出口，并单独开启系统流量接管。首次授权使用 macOS 系统窗口或 Windows UAC；取消不会显示为接管成功。
3. 查看当前接管状态与已观察连接。没有业务流量样本、未接管或证据过期时，结论不会给出绿色通过。
4. 需要环境适配时，再开启环境防护。该操作也会核验网络条件；环境检测得分不证明账号安全。
5. 关闭系统接管后，本机代理仍可使用；从托盘退出应用才会停止内核。需要完全停止接管前先结束环境防护。

macOS 需要更严格的会话控制时，在网络页选择“开启严格模式”并确认网络重连与阻断范围。首次需更新/授权安装本地助手。严格模式期间环境适配可以独立关闭，但系统接管与阻断保留；退出应用仍会断流。恢复联网可再次打开应用选择“关闭严格模式并恢复联网”，或在管理员终端执行：

```sh
sudo /Library/PrivilegedHelperTools/com.envguardcc.kernel-recover
```

酒店/机场门户认证目前应明确关闭严格模式后处理，完成后重新开启并验证；没有自动扩大直连范围或临时放行整个浏览器的降级路径。Windows 严格模式按钮不可用，不把普通代理冒充 WFP 阻断。

`direct` 模式在界面显示为“其他直连”：Claude 域名仍经固定组，其他流量直连。`global` 仍保留明确的内网豁免。只有退出/关闭接管才能结束系统级 TUN 接管。

若需要替换默认 IP 情报探测，可在启动前设置 `CHECKCC_NET_CORE_EXIT_PROBE_URL` 为自己的 HTTP(S) JSON 端点。支持 `ip`、`country_code`（或 `countryCode`）、`country`、`city`、`timezone`（字符串或 `{id}`）；该请求经指定节点发出。基础代理转发不要求 IP 情报服务可用，依赖地区识别的环境适配会明确失败。
