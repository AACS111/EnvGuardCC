# 浏览器网络保护

迷惑层开启时，WebRTC 保留原生接口并强制 ICE relay-only，构造及 setConfiguration 均受限制。无 TURN 中继时不会产生直接候选地址；需要 WebRTC 的通话应用可能因此无法建立连接。显式选择禁用 WebRTC 的独立操作仍可用。

本机助手启动的隔离 Chrome/Edge 与桌面实例使用网关选定的 HTTP/HTTPS 上游代理。代理来源依次为 CHECKCC_PROXY、代理环境变量、Windows 静态系统代理。带认证的代理暂不支持，执行器会明确报错；建议使用本机混合代理端口。没有配置代理时保持原网络，不会凭空改变公网出口。

有代理时禁用 QUIC，并阻止目标域名本地 DNS 回退，域名由代理解析。代理自身及本机助手地址允许本地解析。代理必须可用；代理故障时不回退到直连。此配置固定在进程启动时，改变代理后需关闭并重新启动受保护实例。关闭迷惑层撤销接口覆盖，但不改变已启动进程的网络路由。

接口策略覆盖本机检测页与 claude.ai；只影响助手管理的实例与当前明确接入的检测页，不修改系统全局配置。已有页面和已经建立的连接需刷新或重启后重新验证。

浏览器可达性探测仍记录真实结果。跨站 TypeError、第三方地域字段缺失、未知 IP 情报不被伪造为通过；代理路由成功也不等于目标网站业务可用。不改写测试分数或第三方响应。

验证：node --test --test-timeout=35000 scripts/check-environment-runtime.mjs

“启动保护”只同步配置和已接入的实例，不自动打开浏览器窗口或页面。没有受控浏览器连接时，浏览器接口和实际请求头保留为未验证，整体可能显示“部分生效”。如需在独立受保护浏览器中检测，可显式接入；该操作会打开本机检测页和 Claude。网关开启不代表普通 Chrome 窗口、现有标签页或其他程序自动获得接口保护。
