# EnvGuardCC macOS 版实施计划

实施记录，2026 年 10 月 31 日。

沿用现有 Electron、Next.js 和本机 Node 服务，先交付 Apple Silicon 可用版本，再补齐系统时区、Claude 桌面端和 FlClash 联动。实现顺序由真实依赖决定；不能接入的能力在界面说明原因，不能用启动成功或模拟结果代替实际生效。

阶段零至阶段三已完成当前可支持的源码适配与限制处理；阶段四仍待实施。阶段二、三的操作步骤、实测范围和客户端限制见 [实施结果](MACOS-STAGE23-RESULTS.md)，不将平台或第三方客户端受限的能力计为已验证。

## 一 实施基线和目标

源码基线为 [AACS111/EnvGuardCC 的 b4d27d5](https://github.com/AACS111/EnvGuardCC/tree/b4d27d5161850a50ff06bb617adfb13699c5619f)，版本为 0.1.0。实施前已核对上游未更新，保留 MIT 许可证及原作者信息。阶段零和阶段一已在基于该提交的工作树中完成，但实现尚未提交；macOS 打包、签名、分发和 Finder 安装验证属于后续阶段，不在已完成范围内。

按用户指定的 [Stop That Shit skill](https://github.com/lennney/stop-that-shit/blob/edfdec935e8a345caa24dc42b26411a12c25ad9c/codex-plugin/skills/stop-that-shit/SKILL.md) 控制范围：优先修改已有实现，必要时提取小函数；只增加能补上实际缺口的适配和验证。此处应用 skill 的工作规则，不安装 Guard hooks 或更改全局配置。

首个交付版本面向 Apple Silicon 原生运行，包含检测界面、本机助手、API 网关、受控 Chromium 浏览器（先覆盖 Chrome/Edge）、保护启停及配置恢复。系统时区、Claude 桌面端和 FlClash 分阶段加入；若 Claude 当前版本限制接入，交付时明确列出支持范围。

Intel 版和 Universal 包后续单独处理。最低 macOS 版本仍未确定；阶段零和阶段一只在 macOS 27.0 的 Apple Silicon 机器上验证，不能据此承诺更旧系统。需在目标系统实际运行后，才能对外声明支持范围。

## 三 阶段零 验证关键接入条件

状态：已完成。目标 Mac 上的实际版本、可用性和限制见 [macOS 阶段零/一结果](MACOS-STAGE01-RESULTS.md)。

目标是确定能实施哪些能力，并尽早发现会改变方案的限制。

1. 在工作目录取得指定源码，记录目标 Mac 的系统、架构、Node 和包管理器版本。按现有锁文件安装依赖，核对 `classic-level` 能加载；检查现有 `pnpm-workspace.yaml` 中原生依赖构建配置是否被所用 pnpm 接受，遇到实际问题再修正。
2. 尝试现有开发入口，确认 Electron 能显示页面、本机助手和网关能连接。遇到阻止启动的 Mac 路径问题，仅做必要适配。
3. 找到已安装 Chrome/Edge 的实际可执行文件，用临时用户目录验证调试管道、页面采样、语言覆盖和撤销。浏览器控制范围先限定这两种 Chromium 浏览器。
4. 只读检查 Mac 版 Claude 的应用包、可执行文件、版本和语言资源。在独立配置目录验证启动参数是否被接受，是否转交已有实例，以及能否建立调试连接。
5. 读取当前代理形式和时区。此阶段不写系统时区、不改 FlClash 配置、不使用个人浏览器目录或真实账号请求来证明接入。

交付结果：记录机器和客户端版本、可用启动方式、受控浏览器结果，以及 Claude 的启动和调试接入结论。仅启动进程成功不能证明请求经过网关；调试接口不可用时，后续仍可完成检测、网关和受控浏览器版本。

## 四 阶段一 完成 Mac 桌面基础

状态：已完成源码开发范围。macOS 打包、签名、分发及 Finder 安装仍属阶段四。

涉及 `desktop/main.mjs`、`environment-runtime.mjs`、开发启动脚本及必要的小型平台函数。

- 应用定位覆盖 `/Applications`、`~/Applications`，并保留已有自定义可执行文件入口。应用包内可执行文件优先依据 `Info.plist` 定位，路径通过参数传递，支持空格和中文。
- 仅把重复使用的应用路径、时区和代理操作提取到小模块；不建立通用驱动框架、插件注册系统或新的后台服务。
- 正式版使用 Electron 的用户数据目录保存配置、备份和受控资料，不在应用包内部写入状态。保留现有数据目录兼容逻辑。
- 发布模式按平台选择内置 Node；开发模式继续使用开发环境 Node。Finder 启动不依赖终端配置的 PATH。
- 首版明确采用“关闭主窗口即退出并恢复”的行为，与现有程序一致；增加 Mac 应用菜单及 `Cmd+Q`。后续若改为关闭窗口保留后台运行，再补窗口重新打开流程。
- 本机服务维持回环监听、现有会话认证和单实例约束。端口被其他程序占用时给出可操作的错误，不终止占用者。

交付结果：开发模式可稳定打开和退出；退出完成后，本次创建的助手、网关及受控进程按既有职责关闭，端口得到释放。

## 五 阶段二 交付检测 网关和受控浏览器

状态：已完成源码适配；受控 Chrome 与实际请求头已验证，Mac 安装包环境的验证仍随阶段四执行。

涉及 `gateway-proxy.mjs`、`environment-runtime.mjs`、`local-repair.mjs`、`protection-service.mjs` 和对应前端组件。

### 代理与网络

保留已有显式代理及环境变量的优先级，增加 Mac 当前有效静态 HTTP/HTTPS 代理读取，可先用系统提供的 `scutil --proxy`。解析结果须区分“未启用静态代理”“无法自动解析”和“读取失败”。

PAC 首版不增加解释器。遇到 PAC 且无法确定转发路径时，说明需要提供 HTTP/HTTPS 代理地址；若 Finder 运行场景缺少配置入口，只补一个必要的地址字段。SOCKS 地址沿用现有不支持的提示，不擅自当作 HTTP 代理。TUN 模式按真实系统路由运行，不把缺少静态代理配置判成未经过 VPN。

受控浏览器和网关沿用选定上游。已选择代理而代理故障时，保留现有失败行为，不静默回退直连。改变代理后按现有生命周期重启受控实例，再采样结果。

### 能力与界面

在现有助手会话响应上补充少量能力字段，涵盖受控浏览器、Claude 桌面启动、桌面调试接入和系统时区操作。同步更新 `HelperSession` 类型及调用者，替换相关 `win32` 按钮判断。

能力字段表示可尝试的操作；实际结果继续使用现有已验证、未验证、失败和已恢复状态。没有连接目标页面时，不复用上次的通过结果；不新增一套与现有保护状态并行的状态机。

交付结果：用户可完成“检测 → 开启保护 → 接入受控浏览器 → 读取目标页面结果 → 关闭并恢复”。从 Finder 启动的打包版本也必须完成同一流程，该项随阶段四验证。

## 六 阶段三 补齐系统和客户端能力

状态：系统时区、普通客户端打开与 FlClash 联动已实现。当前 Claude 的独立资料/调试接入不可宣称支持；FlClash 0.9.2 需由自身执行重载，详见实施结果。

### 系统时区

Mac 使用 IANA 标识，例如 `Asia/Tokyo`；Windows 继续使用现有映射。把读取、写入和校验接入同一业务流程，保留平台对应的原始值，旧备份按原平台解释。

首次交付默认读取系统时区；用户明确选择同步后才执行系统写入。实现可从系统 `systemsetup` 能力开始，在实际需要时使用 macOS 授权流程。管理员认证交给系统，不在网页收集或保存密码。只提升执行固定时区操作的最小范围，不让整个应用以管理员身份运行。

修改前保存原始值，修改后重新读取，关闭保护或退出时恢复并核对。用户取消授权、恢复仍需授权或系统自动时区覆盖写入时，显示实际结果并保留恢复记录。强制结束进程后，在下次启动处理未完成恢复；不承诺强制结束瞬间能执行清理。若需处理自动时区开关，先核实系统行为，只有实际修改了开关才承担对应恢复。

交付结果：完成一次真实修改和恢复；取消授权不会被显示为成功；恢复失败后仍保有原始值和重试入口。

### Claude 桌面端

先完成应用包、资源和独立配置路径适配，再验证当前客户端是否实际读取该配置。语言修改继续限定于本工具管理的资料目录，不能为完成演示而修改用户日常 Claude 数据。

分别验证托管启动、请求转发和调试接入。若客户端只允许启动而拒绝调试，界面仅报告已启动，接口保护保持不支持或未验证；代理环境变量被传入也不能算实际网络已经过网关。

`classic-level` 先在目标架构和打包后的实际运行环境加载、读写临时数据库。只有出现预编译缺失或运行时不匹配，才定向重建相关原生依赖。

交付结果：列明实测 Claude 版本，以及该版本支持的启动、语言、网络与页面接入能力。客户端接入受限不阻止交付其余已完成功能。

### FlClash 联动

在基础版可用后实施。先只读确认 Mac 版 FlClash 的实际数据目录、当前配置格式、配置重载方式和系统代理或 TUN 状态，不把 Windows 路径直接替换后视为完成。当前 v0.9.2 联动采用原生 FlClash 重新应用配置，工具核验策略及回程端口；不通过不更新监听器的 REST 响应判定已重载。

2026 年 10 月 31 日已在真实 FlClash 0.9.2 GUI 上补测通过；开启外部控制器后需先让 FlClash 重载一次，重启后需确认内核处于运行状态。记录见 [FlClash 真实 GUI 联动验证](MACOS-FLCLASH-GUI-VERIFICATION.md)。

复用现有配置准备、备份、哈希冲突检测和恢复流程。用临时或专用配置完成路由验证后，再接入日常使用入口。只有流量层需要独立于主窗口持续存在，才增加 LaunchAgent，并同时实现停用和恢复；不默认新增常驻任务。

交付结果：流量实际经过预期链路，回程不循环，配置外部变更不会被覆盖，恢复后原分流正常。仅生成文件或显示 `applied` 不代表内核已重载。本项不阻塞首个基础版。

## 七 阶段四 打包和发布

状态：本地试用包已完成（ad-hoc 签名；按当前交付定位不申请 Developer ID 和公证，首次打开需在隐私与安全性中授权）；本机已安装到 `/Applications`，异机验证待补。记录见 [阶段四结果](MACOS-STAGE4-RESULTS.md)。

沿用 `@electron/packager` 生成 `.app`，ZIP 使用系统 `ditto`，DMG 使用系统 `hdiutil`，没有为 macOS 引入 `electron-builder`。新增 Mac 打包入口并生成 `.app`、DMG 和 ZIP，加入 Mac 图标；安装路径和运行说明对应新平台。

构建使用同一目标架构的 Electron、内置 Node 和原生依赖，不把 Intel Node 复制到 arm64 应用。保留现有静态页面导出和产物完整性检查，不额外引入一套清单与校验工具。

先生成本地可审阅的安装产物。当前交付定位为本地试用，不申请 Developer ID、Hardened Runtime 和公证；首次打开需在系统设置 > 隐私与安全性中授权。若后续公开分发，再完成 Developer ID 签名、Hardened Runtime 和公证。签名需覆盖内置可执行文件及原生模块；权限以实际运行需要为准，不预先添加宽泛 entitlement。没有证书和公证凭据时，可交付明确标注状态的本地试用包，公开分发就绪状态单独报告。

增加匹配 arm64 的 macOS 构建任务。首轮先上传构建产物供下载验证；发布时统一处理 Windows 和 Mac 资产，避免两个流程覆盖同一 `SHA256SUMS.txt` 或相互改写发布说明。校验值覆盖最终分发文件。

在另一台未安装开发依赖的目标 Mac 上，从 Finder 安装并运行，检查内置 Node、原生依赖、浏览器定位和恢复流程。最低系统版本若没有对应验证条件，只能标成待验证；Intel 支持也需单独运行证据。

交付结果：安装产物、安装说明、明确的支持范围及签名状态，以及与最终文件一致的校验值。

## 八 保留有价值的验证

验证围绕用户行为和现有保证，复用 Node 自带测试及已有脚本，不为移植增加新测试框架。

| 检查范围 | 保留的最小验证 | 使用时机 |
| --- | --- | --- |
| 页面与本机服务 | 页面可读可操作、助手和网关可连接，端口占用不影响其他程序 | 桌面入口或打包结构变化后 |
| 受控浏览器 | 真实 Chrome/Edge 中首次打开、刷新、应用和撤销各走一遍 | 浏览器路径或执行器变化后 |
| 网络转发 | 本地可控上游证明转发路径；代理故障不能回退直连，已有认证边界仍生效 | 代理读取或转发逻辑变化后 |
| 配置恢复 | 临时目录验证原值恢复、无关字段保留、失败保留备份；系统时区另做一次真实授权与恢复 | 恢复逻辑或系统操作变化后 |
| Claude 接入 | 真实客户端验证启动归属、配置目录和接入能力 | 实现该能力或目标客户端版本改变后 |
| 安装包 | 从 Finder 启动、内置运行环境可用、正常退出及重新打开 | 最终打包后 |
| Windows 兼容 | 在 Windows 运行受公共模块修改影响的现有检查 | 公共模块修改完成后；不把 Mac 上的模拟结果算作通过 |

优先复用 `check-environment-runtime.mjs`、`check-desktop-launcher.mjs`、`check-shutdown-restore.mjs` 和相关网关用例。修改保护控制或重连流程时，再运行对应现有用例。FlClash 检查只在实施该项时运行。修改完成后执行适用的 lint 和实际构建，同一最终状态通过后不重复全量运行。

### 从计划中删除或收窄的检查

- 桌面检查中的 `cardHeight === 224` 改为确认工作台样式已加载、内容和主要操作可用；不把 CSS 布局方式固定为必须是 `grid`。
- Mac 发布检查不依赖中文按钮文案、固定按钮数或固定标签页数量；只检查对应操作和结果。与明确产品约定相关的现有组件测试，按其职责保留。
- 不新增“源码包含 `darwin`”、文件存在、复制实现逻辑或只证明 mock 返回成功的测试。
- 不为路径拼接和简单平台选择穷举大量组合；只覆盖实际支持的系统级安装、用户级安装和自定义路径。
- 不为未改动的评分、授权生成器及其他模块补测试，不引入全站截图基准、性能基准或覆盖率指标。
- 已有重复检查只有在核实覆盖同一行为且没有独立保证后才合并；认证、原始备份、失败恢复和网络不回退等用例保留。
