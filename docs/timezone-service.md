# macOS 系统时区服务

macOS 13 及以上在首次开启保护时自动绑定专门的系统时区服务，由用户在系统弹窗中批准，此后正常修改、恢复时区复用该服务。页面不显示连接设置或服务管理控件。开源源码编译和 ad-hoc 签名构建均可使用；使用者不需要 Apple Developer 账号。

## 自动管理

- 首次需要修改系统时区时安装并请求一次系统授权。已就绪时直接复用；更新了原生客户端或服务二进制时，下一次显式操作重新请求授权。
- 拒绝授权或安装失败时报告部分生效，保留原始备份，不在后台循环弹窗。用户显式关闭或重新开启保护时允许重试。
- 服务执行失败后不自动换通道重复操作，避免部分成功后发生二次修改。
- 当前构建没有原生组件或旧版 macOS 不支持时，保留按次系统授权作为兼容回退。正常检测不申请管理员权限。
- 服务与应用功能绑定，没有面向用户的安装、模式选择、更新或卸载面板。固定卸载接口仅供系统清理和维护使用，不能在保护尚未恢复时移除服务。

## 权限边界

服务端是独立的 Swift 原生程序，不以 root 身份运行 Electron、Node、网页或任意脚本。仅提供连通检查、设置有效本机 IANA 时区/自动时区开关、卸载自身三个 XPC 操作。命令路径和参数格式固定，没有任意执行命令或读写任意文件的接口，不保存管理员密码。

XPC 校验客户端精确代码签名；每次修改前确认调用者为当前控制台登录用户。客户端检查服务文件由 root 持有、无组/其他用户写权限且非符号链接，再使用服务签名要求校验 XPC 对端。服务串行执行变更，并对系统命令设超时。应用仍在用户目录保存原始设置，成功回读后才清理恢复备份。

本实现使用首次管理员批准的 root-owned LaunchDaemon 安装，兼容开源、临时签名构建；没有使用要求应用公证的 SMAppService LaunchDaemon 注册途径，也没有修改系统授权数据库或设置全局免密 sudo。

安装位置固定为：

- `/Library/PrivilegedHelperTools/io.github.aacs111.envguardcc.timezone`
- `/Library/LaunchDaemons/io.github.aacs111.envguardcc.timezone.plist`

安装过程在 root-only 暂存目录中复制并校验二进制和 plist，校验通过后才替换。升级失败时尝试恢复原服务。root-only 路径的权限或签名异常不会被当作正常服务使用。安装卸载不是普通扫描的自动动作，首次绑定由开启保护触发，并经系统管理员弹窗批准。

## 开发验证

```bash
node scripts/build-timezone-service.mjs
node --test scripts/check-timezone-service.mjs
```

预览测试不自动安装系统服务。首次本机验证需要用户在开启保护时批准安装，并输入系统密码或使用 Touch ID；密码不经过应用或聊天。正式对外发布仍建议由维护者统一完成 Developer ID 签名和公证，以改善下载与安装体验，这不是每个开源使用者的前置要求。
