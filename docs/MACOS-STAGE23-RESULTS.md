# EnvGuardCC macOS 阶段二与阶段三实施结果

2026 年 10 月 31 日。保留阶段零、一的已有改动；改动尚未提交或推送。

## 已实现的功能

| 功能 | 当前行为 |
| --- | --- |
| Mac 代理识别 | 读取系统静态 HTTP/HTTPS 代理，区分未启用、PAC/SOCKS 不支持和读取失败；读取失败不会被当作可直接连接 |
| 应用代理设置 | 连接设置可保存手动 HTTP/HTTPS 代理，或使用系统路由；只保存本应用配置，不修改系统代理。原有显式环境变量优先级保留 |
| 受控浏览器 | Chrome/Edge 应用定位、独立资料、页面接口及请求语言保护；代理地址改变时重建受控进程；页面关闭、断连或配置变化后重新核验 |
| 能力界面 | 助手报告时区读写、浏览器和客户端能力；界面按能力决定可操作项，不再把非 Windows 一律视为不可执行 |
| 系统时区 | Mac 使用 IANA 标识。只有明确点击系统时区操作才请求管理员授权，修改前保存原值，回读核对，支持恢复与退出恢复 |
| Claude 桌面端 | 当前 Mac 客户端提供普通打开入口；不写个人资料、不注入代理，不把打开请求当作托管或保护成功 |
| FlClash | Mac 配置定位、回程策略选择、准备、写入、重载核验、真实转发计数、恢复和外部修改冲突保护；入口随应用管理 |

`js-yaml` 已移入运行时依赖，并补入既有桌面构建的运行时复制列表。没有新增第三方运行时库、特权常驻服务或 LaunchAgent。

## 使用方法

在当前本地工作副本运行 `pnpm dev:electron`，展开概览中的“连接设置与 FlClash”。

### 检测 网关与浏览器

1. 默认自动读取系统静态代理。使用 PAC、仅 SOCKS 或希望明确指定路径时，选择“指定 HTTP/混合代理”并保存地址。手动入口不接受带认证的地址，受控浏览器仍保留这一限制。
2. “使用系统路由”可能经过现有 TUN；没有静态代理不等于没有经过 VPN。本工具不据此宣布整机流量或 DNS 已受保护。
3. 启动保护后，点击“接入并验证浏览器”。该操作明确打开独立浏览器的检测页和 Claude 页面，不接管个人浏览器窗口。
4. 界面分别报告目标页面接口和实际请求语言头；配置已保存或进程已启动不会自动算作通过。接入后触发重新采样，后续状态持续刷新。

### 系统时区

在系统时区检测项中选择目标并点击设置。此操作影响本机其他应用，macOS 管理员认证由系统窗口完成，不在页面收集密码。Mac 不会在启动保护时自动改变系统时区。

原始备份包含平台信息，反复切换目标不会覆盖第一次的原值。恢复成功并核对后清除备份；取消授权、回读失败或恢复未完成时保留备份。关闭保护及退出也尝试恢复本应用负责的时区改动。

### FlClash 联动

本轮使用官方 [FlClash v0.9.2](https://github.com/chen08209/FlClash/releases/tag/v0.9.2) 的 arm64 安装镜像，核对官方 SHA256SUMS，并通过应用代码签名验证。解压应用保留在项目依赖目录的验证区，未安装到 `/Applications`。

该版本在 Mac 使用系统偏好保存当前配置，应用数据目录来自其 Application Support 路径；代码按这一版本的实际实现适配，并保留显式目录/文件覆盖入口。联动需要 FlClash 已选中配置，且开启仅本机、带认证的外部控制，用于核验内核状态。

1. 选择实际回程策略组，点击“准备联动”。原节点、原组及 DIRECT/REJECT 规则保留。
2. 点击“写入联动配置”，然后在 FlClash 中重新应用并启动当前配置（确认内核处于运行状态）。
3. 回到 EnvGuardCC 刷新连接状态。只有联动策略及回程端口都存在，才报告内核已加载；随后用真实请求和转发计数判断覆盖。
4. 点击“恢复原配置”会先写回原文件。到 FlClash 重新应用当前配置后，再点击恢复完成核验。等待重载期间保留拦截入口。
5. 若退出时内核仍使用联动配置，应用提示完成 FlClash 重载后重试退出，不提前释放仍在使用的入口。外部订阅或配置变动造成哈希不符时，拒绝覆盖并保留备份。

这是需要 FlClash 配合重载的流程。v0.9.2 所用内核的 REST 配置重载未更新监听器，不能用一次 REST 成功响应代替重载完成。对应源码为 [Clash.Meta executor.go](https://github.com/chen08209/Clash.Meta/blob/c5062921054902b25215a6a933e72ccd714c9bfa/hub/executor/executor.go)，实际验证也观察到这一差异。因此没有加入无法可靠工作的“自动重载”。

2026 年 10 月 31 日补充：已在用户实际使用的 FlClash 0.9.2 GUI 上完成一次真实联动（真实 profile、真实内核、原策略组出口）。GUI 生成运行配置时保留 `listeners`，回程端口、真实转发计数与恢复均通过；同时发现开启外部控制器后需先让 FlClash 重载一次，重启后还需确认内核处于运行状态。记录见 [FlClash 真实 GUI 联动验证](MACOS-FLCLASH-GUI-VERIFICATION.md)。

入口只承载 HTTP/TCP CONNECT，不安装根证书、不解密 HTTPS，不提供 UDP 转发保证。强制结束进程或断电后需要重新启动应用处理未完成恢复，不能承诺在强制结束瞬间清理路由。

## 实际验证结果

### 浏览器和网关

- 在 Electron 界面完成了启动保护、保存代理及接入浏览器。
- 独立 Chrome 的 Claude 页面指定接口与实际请求语言头均得到已验证结果，观察到 `zh-HK` 与随后出口变化后的 `en-US` 请求语言。
- 新增实际 Chromium 检查：代理地址改变后进程 ID 改变，新请求到达新代理，接口策略保留。
- 浏览器结果接入现有状态监听，关闭保护或助手断连时不继续显示旧的已验证结果；接入完成后清理已过期的浏览器问题说明。
- 本机接口额外验证：未认证代理写入返回 403，正确会话保存返回 200，不支持的 SOCKS 地址返回 400。

### 系统时区

- 实际从 `Asia/Shanghai` 切换到了 `Asia/Hong_Kong`，最终恢复并核对为 `Asia/Shanghai`；两者均为 UTC+8。
- 第一次写入后的立即回读遇到 macOS 切换时短暂的文件缺失，因此请求报告失败并保留原始备份。已针对这一实际问题增加有限等待回读及本机时区文件检查，并增加回归用例。
- 恢复授权曾等待超时，随后由用户完成系统授权，使用更新后的适配器确认原值恢复；验证助手的恢复备份已清除、监听已关闭。
- 取消授权、时区非法、本机缺少时区文件及回读不符按失败处理；其中取消与失败分支由隔离测试覆盖，没有再次反复修改真实系统设置。

### FlClash 流量

提供的 `dmit.yml` 只读使用，验证在私有副本进行，源文件哈希未变；没有把节点凭据写入文档或终端结果。

- 原文件两个节点在本轮 FlClash 环境中访问目标出现 502，不能宣布这两个节点可用。
- 为独立验证联动链路，在验证副本增加并选择本机已可用的 HTTP 代理上游；原有节点保留但没有被该成功用例选中。
- 官方 FlClashCore 在隔离目录中运行，TUN 关闭、未设置系统代理。通过它自身的配置应用及监听器流程模拟 FlClash 重载，未用普通 REST 重载冒充。
- 对 `http://example.com/` 的应用前、联动期间、恢复后三次请求均为 HTTP 200，均收到 577 字节。
- 联动期间记录到 1 条成功 CONNECT、0 次转发失败；策略与回程端口核验通过。
- 恢复在重载前进入等待状态并保留入口，重载后核验成功；副本原文恢复，源文件校验一致。

这组结果证明上述隔离配置和 TCP 路径可运行，不证明所提供节点可用，也不证明所有应用或 TUN 全覆盖。正式 GUI 的导入和重载动作仍由 FlClash 用户完成。

## 验证与后续范围

相关的代理、受控浏览器、保护会话、退出恢复、FlClash 和 Mac 适配共 105 项检查通过。保护控制与评分回归通过；完整 ESLint 通过，最终源码在独立临时目录完成 Next.js 静态生产构建。构建保留上游 TypeScript 5.0.2 的版本推荐提示，未为此升级依赖。

最后补测开发退出恢复：使用临时目录放入明确不属于本平台的测试备份，确认恢复失败时助手、网关和 Next 均保留；移除测试故障后重试退出，助手和网关监听关闭，Next 收到 SIGTERM 并退出。对应修改后的 16 项开发、恢复和 FlClash 检查再次通过。独立助手同样在恢复失败时保留监听和重试能力，避免提前释放仍被 FlClash 使用的入口。

新增检查针对实际的跨平台行为、代理切换和恢复约束，没有增加像素、文案计数或源码字符串门禁。
