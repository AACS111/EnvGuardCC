# 网络波动与休眠恢复 Implementation Plan

> **For agentic workers:** 使用 executing-plans 在当前会话逐项执行，完成后独立复核。

**Goal:** 短暂网络异常不停止健康内核；断网启动失败可自动重试；休眠恢复立即重新检查并恢复保护。

**Architecture:** 沿用桌面唤醒通知和保护配置重连入口。在内核后台巡检中区分进程退出与控制接口暂时失败，通过计时器间隔检测休眠，取消旧退避并作废网络证据。

**Tech Stack:** Node.js ESM、node:test；无需新增依赖。

**Spec:** 本次用户要求：修复已复现问题，并在电脑休眠唤醒后尽快自动建立内核和保护。

## Global Constraints

- 保留用户已有改动；不合入 main，不提交或发布。
- 显式停止后不得自动拉起；未验证的 Claude 出口仍保持阻断。
- 系统网络尚未恢复时持续等待，不承诺固定恢复耗时。

## Review Focus

- 首次启动失败尚未建立巡检。
- 控制接口单次失败和持续失败。
- 无窗口唤醒通知、网卡地址不变的休眠恢复。
- 唤醒时网卡晚于后台恢复，以及内核进程退出。
- 用户主动停止取消所有自动恢复。
